# Инкремент T-1 — Личный трекер доходов и расходов

## Статус

Выполнено

## Контекст

Приложения личного учёта доходов и расходов в проекте нет: репозиторий содержит только
документацию (`specification/`) и правила написания кода (`.claude/conventions/`), кода, модулей и
сборки нет. Поэтому инкремент создаёт приложение с нуля — от модели данных до экранов отчёта.

Продуктовая суть задачи зафиксирована в `intent.md` этого же тикета: однопользовательское
веб-приложение без входа, где пользователь вносит вручную поступления, траты и переводы между
своими счетами с разбивкой по категориям и счетам, видит остатки по счетам и получает отчёт за
произвольный период.

Ключевые ограничения, из которых исходит план:

- данные первой версии живут **в браузере**; серверная часть на Node.js/Express закладывается на
  будущее и в этой версии не обслуживает данные пользователя;
- один пользователь, без регистрации и входа;
- одна валюта на всё приложение, выбирается в настройках;
- переводы между своими счетами — самостоятельный тип операции: в отчёте идут отдельной строкой
  и не попадают ни в доходы, ни в расходы;
- лимиты по категориям, импорт из банка, уведомления, несколько валют — вне объёма.

## Решения по ходу реализации

- **Монорепо с двумя независимыми npm-проектами**: `frontend/` (React + TypeScript + Vite) и
  `server/` (Node.js + Express + TypeScript). Общего пакета с типами нет: в первой версии домен
  реализован только на стороне frontend, и общий пакет связывал бы две половины, между которыми
  ещё нет обмена данными.
- **Данные — в localStorage за абстракцией репозитория**: весь доступ frontend к данным идёт через
  интерфейс `DataRepository`. Реализация v1 — `LocalStorageRepository`; когда появится сервер,
  подменяется реализация на API-клиент без переписывания доменной логики и экранов.
- **Деньги хранятся в минорных единицах** (целые копейки/центы), а не во float: суммы приводятся
  к целым минорным единицам при вводе и форматируются только на отображении и при экспорте.
- **Сервер в этой версии — каркас и контракт**: Express-приложение поднимается, содержит слои
  `routes → services → repositories` и описывает доменные операции в OpenAPI-контракте
  (`server/openapi/openapi.yaml`), но не хранит данные пользователя и не участвует в работе v1.
  Контракт фиксирует границу, по которой v2 заменит локальное хранилище на API.
- **Начальный баланс счёта обязателен** и задаётся при создании счёта; остаток счёта =
  начальный баланс + операции по счёту. Операция, уводящая остаток в минус, **не сохраняется**,
  пользователю показывается понятная ошибка.
- **Сравнение в отчёте — двумя способами**: с предыдущим календарным месяцем и с предыдущим
  периодом той же длины (непосредственно перед выбранным).
- **Стартовый набор категорий — JSON-файл в репозитории** (`frontend/src/data/seedCategories.json`),
  применяется один раз при первом запуске. Дальше пользователь свободно переименовывает, дополняет
  и удаляет категории.
- **Удаление справочника не удаляет операции**: операции остаются в истории и теряют привязку,
  в интерфейсе показываются как «без категории» / «без счёта».
- **Стартовые счета не создаются автоматически** — пользователь заводит свои (наличные, карта, вклад и т.п.).
- **Язык интерфейса — только русский**, i18n-слой не заводится.

## Цель

1. Пользователь заводит счета (название, тип, начальный баланс) и видит текущий остаток каждого.
2. Пользователь вносит операции трёх видов: доход, расход, перевод между своими счетами — с
   указанием суммы, даты, категории, счёта (для перевода — счёта-источника и счёта-получателя) и
   произвольного комментария. Операцию можно отредактировать и удалить.
3. Попытка увести остаток счёта в минус отклоняется с понятным сообщением; операция не сохраняется.
4. Категории: готовый набор на старте, пользователь может создавать свои, переименовывать и удалять;
   удаление не трогает историю операций.
5. Отчёт за выбранный период (месяц или произвольный диапазон дат) показывает:
   - итоги: доходы, расходы, переводы (отдельной строкой) и итог (доходы − расходы);
   - разбивку доходов и расходов по категориям;
   - разбивку операций по счетам;
   - динамику по месяцам внутри периода;
   - сравнение с предыдущим календарным месяцем и с предыдущим периодом той же длины;
   - графики и топ расходных категорий.
6. Отчёт выгружается в CSV и Excel.
7. Валюта выбирается в настройках и отображается во всех суммах.

## Изменения в коде

### Структура репозитория

```
frontend/            # React + TS + Vite, самостоятельный npm-проект
  src/
    domain/          # чистая доменная логика и типы, без React и без хранилища
    data/            # интерфейс репозитория, реализация на localStorage, seed-категории
    features/        # экраны: операции, счета, категории, отчёт, настройки
    ui/              # переиспользуемые компоненты (таблицы, формы, графики, модалки)
server/              # Node.js + Express + TS, самостоятельный npm-проект (каркас + контракт)
  src/
    routes/          # express-роуты, отдающие 501/заглушку до появления БД
    services/        # сервисный слой домена
    repositories/    # интерфейсы репозиториев + будущие реализации
  openapi/openapi.yaml
```

### Frontend — доменный слой

`src/domain/types.ts` — сущности предметной области:

```ts
export type CategoryKind = 'income' | 'expense';
export type OperationType = 'income' | 'expense' | 'transfer';

export interface Account {
  id: string;
  name: string;
  type: string;            // свободный справочник: «Наличные», «Карта», «Вклад»
  initialBalance: number;  // минорные единицы
  createdAt: string;
}

export interface Category {
  id: string;
  name: string;
  kind: CategoryKind;
  isSeed: boolean;
  createdAt: string;
}

export interface Operation {
  id: string;
  type: OperationType;
  amount: number;          // минорные единицы, всегда > 0
  date: string;            // ISO-дата YYYY-MM-DD
  accountId: string | null;        // null — «без счёта» (счёт удалён)
  targetAccountId: string | null;  // заполняется только для transfer
  categoryId: string | null;       // null — «без категории» (категория удалена)
  comment: string;
  createdAt: string;
  updatedAt: string;
}

export interface Settings {
  currency: string; // код валюты, по умолчанию RUB
  version: number;  // версия формата хранимых данных — для будущих миграций
}
```

`src/domain/money.ts` — перевод строки/числа в минорные единицы, форматирование суммы с двумя
знаками и валютой, разбор значения из поля ввода (запятая и точка как разделитель).

`src/domain/operations.ts` — правила предметной области, не зависящие от хранилища:

- `calculateAccountBalance(account, operations): number` — начальный баланс + вклад операций;
- `validateOperation(op, accounts, categories, operations, options): string | null` — проверяет
  положительность суммы, корректность даты, наличие счёта и категории нужного вида, различие
  счетов в переводе и **недостаточный остаток** (для расхода — остаток счёта после операции ≥ 0;
  для перевода — то же для счёта-источника); при правке операции её собственный вклад в остаток
  исключается (`options.excludeOperationId`);
- `effectOnAccount(operation, accountId)` — вклад операции в остаток счёта: доход `+amount`,
  расход `−amount`, перевод `−amount` для источника и `+amount` для получателя.

`src/domain/report.ts` — расчёты отчёта, чистые функции над массивом операций:

- `buildReport(operations, period): Report` — итоги (доходы, расходы, переводы, итог), разбивки
  по категориям и счетам, месячная динамика;
- `buildComparison(operations, period): Comparison` — значения для предыдущего календарного месяца
  и для предыдущего периода той же длины;
- период задаётся границами `from`/`to` включительно; операция попадает в период по полю `date`.

### Frontend — слой хранения

`src/data/repository.ts` — интерфейс, скрывающий способ хранения:

```ts
export interface DataRepository {
  listAccounts(): Account[];
  listCategories(): Category[];
  listOperations(): Operation[];
  getSettings(): Settings;
  saveAccount(account: Account): void;
  removeAccount(id: string): void;
  saveCategory(category: Category): void;
  removeCategory(id: string): void;
  saveOperation(operation: Operation): void;
  removeOperation(id: string): void;
  saveSettings(settings: Settings): void;
}
```

`src/data/localStorageRepository.ts` — реализация: четыре ключа в localStorage
(`accounts`, `categories`, `operations`, `settings`), чтение/запись JSON, применение стартового
набора категорий из seed-файла при первом запуске (если `categories` ещё нет).

`src/data/seedCategories.json` — стартовый набор категорий доходов и расходов (типовой: зарплата,
прочие доходы, продукты, транспорт, жильё, коммунальные услуги, здоровье, развлечения, одежда,
прочее). Файл — данные, а не логика: меняется без правки кода.

`src/data/storage.ts` — тонкая обёртка над localStorage с обработкой недоступного хранилища
(приватный режим браузера) и повреждённых данных: сообщение пользователю вместо падения.

### Frontend — экраны

- `src/features/accounts/` — список счетов с текущим остатком, форма создания/правки (название,
  тип, начальный баланс), удаление с подтверждением. Тип счёта — свободный текст с подсказками
  по распространённым значениям.
- `src/features/categories/` — список категорий с разделением на доходы и расходы, создание,
  переименование, удаление с подтверждением (с указанием, что история операций сохранится).
- `src/features/operations/` — список операций с фильтрами (период, счёт, категория, тип) и
  сортировкой по дате; форма ввода/правки: тип операции (переключатель), сумма, дата, счёт,
  категория (для дохода/расхода), для перевода — счёт-источник и счёт-получатель, комментарий.
  Ошибка insufficient funds показывается у поля суммы, форма не закрывается.
- `src/features/report/` — выбор периода (месяц или произвольные даты), блок итогов, разбивка по
  категориям, разбивка по счетам, месячная динамика, сравнение с двумя предыдущими периодами,
  графики, топ расходных категорий, кнопки экспорта CSV и Excel.
- `src/features/settings/` — выбор валюты.
- `src/App.tsx` — маршруты: `/accounts`, `/operations`, `/categories`, `/report`, `/settings`.

`src/ui/` — таблицы, формы с валидацией, модалка подтверждения, карточки итогов, компоненты
графиков (библиотека построения графиков на выбор по React-экосистеме), пустые состояния.

`src/features/report/export.ts` — выгрузка отчёта: CSV собственной сериализацией (разделитель `;`
для совместимости с русским Excel, `;` в начале — корректная кодировка) и Excel через клиентскую
библиотеку (`.xlsx`). Экспортируется отчёт за выбранный период (итоги + разбивки + месячная
динамика), а не сырые операции.

### Server — каркас и контракт

- `server/package.json`, `server/tsconfig.json` — самостоятельный проект, скрипты `dev`/`build`/`start`.
- `server/src/app.ts` — сборка Express-приложения, подключение `express.json()`, CORS для
  локального frontend, `/api/health`.
- `server/src/index.ts` — запуск сервера.
- `server/src/routes/` — заглушки эндпоинтов домена: `GET/POST /api/accounts`,
  `GET/POST /api/categories`, `GET/POST /api/operations`, `GET /api/reports`, `GET /api/settings`.
  Возвращают `501 Not Implemented` — хранилища на сервере пока нет.
- `server/src/services/`, `server/src/repositories/` — интерфейсы сервисного и репозиторного слоёв
  с теми же доменными типами, что и во frontend, без реализаций.
- `server/openapi/openapi.yaml` — OpenAPI-контракт: сущности, эндпоинты, схемы запросов/ответов,
  коды ошибок. Это граница, по которой вторая версия заменит `LocalStorageRepository` на API-клиент.

### Обработка ошибок

- Ошибки валидации домена (неположительная сумма, нехватка остатка, перевод в тот же счёт,
  отсутствующий счёт) — типизированные доменные ошибки с кодом и сообщением на русском;
  пользовательские ошибки показываются в форме у соответствующего поля, без диалога ошибки;
- недоступное или повреждённое хранилище — сообщение на странице приложения;
- остальные ошибки — без stacktrace в интерфейсе, с записью в консоль.

### Тесты

- `frontend`: Vitest — юнит-тесты доменного слоя (`operations.ts`: правила остатка и блокировки;
  `report.ts`: итоги, разбивки, месячная динамика, сравнение с двумя предыдущими периодами;
  `money.ts`: разбор и форматирование) и тесты репозитория на fake-хранилище.
- `server`: Vitest — smoke-тест health-эндпоинта и проверка, что доменные эндпоинты отвечают 501.

## Совместимость

Существующих данных и пользователей нет — приложение создаётся с нуля, миграции не требуются.
При обновлении приложения данные остаются в localStorage браузера; формат хранимого JSON — версионируется
поле `version` в записи `settings`, чтобы будущий формат читался мигрирующим кодом. Перенос данных
на сервер (v2) — отдельная задача вне объёма этого инкремента; на этот случай в v1 предусмотрена
выгрузка отчёта в CSV/Excel.

## Обоснование решений по результатам разработки

- **Начальный баланс и суммы вводятся в единицах валюты, а хранятся в минорных единицах.** В форме
  пользователю удобнее видеть «1000», а «100000» копеек в поле ввода выглядит ошибкой; пересчёт в
  минорные единицы происходит при сохранении, поэтому точность сумм не теряется.
- **Ошибка «Недостаточно средств» выводится у поля «Сумма», остальные ошибки — над формой.** План
  говорил только про недостаток средств; остальные проверки не относятся к сумме, и выводить их
  под этим полем вводило бы в заблуждение.
- **Операции, потерявшие привязку к удалённому счёту или категории, не влияют на остатки.** У
  удалённого счёта нет остатка, и операция без счёта не может его изменить; в истории такие записи
  остаются видимыми и в отчёте попадают в «Без счёта»/«Без категории». Перевод, потерявший одну из
  сторон, теряет привязку целиком — иначе счёт-получатель получил бы деньги, которых никто не
  списал.
- **Компонент `Field` связывает подпись с полем через `id`.** Без этого подпись не была связана с
  элементом формы, и по ней нельзя было ни перейти с клавиатуры, ни найти поле в тестах.
- **Добавлен тест рендера на jsdom, которого не было в плане.** В окружении нет браузера, поэтому
  единственный способ проверить, что интерфейс действительно работает, — прогнать сценарии
  добавления счёта и отказа при нехватке средств в jsdom-окружении.
- **Графики построены на `recharts`, выгрузка Excel — на `xlsx`, CSV собран вручную.** В плане
  библиотеки не были названы; CSV собран вручную, потому что для него достаточно разделения «;» и
  BOM, а внешняя зависимость ради трёх секций отчёта лишняя.
- **«Итог» в отчёте равен доходам минус расходы; переводы в него не входят.** Переводы — движение
  своих денег между своими счетами, они выводятся отдельной строкой и не меняют общую картину.
