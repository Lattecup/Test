# Хранение данных

## Где живут данные

Пользовательские данные хранятся в браузере (localStorage) и не отправляются на сервер. Серверная
часть не хранит данные пользователя и не участвует в работе приложения. Следствие для
пользователя: очистка данных сайта в браузере удаляет всю историю операций, поэтому для
сохранения отчёта предусмотрена выгрузка в CSV и Excel.

Серверного хранилища и базы данных у приложения нет.

## Доступ к данным

Весь доступ к данным идёт через интерфейс репозитория (`DataRepository`): список и сохранение
счетов, категорий, операций и настроек. Реализация — `LocalStorageRepository`; когда появится
серверное хранилище, реализация подменяется на API-клиент, доменная логика и экраны при этом не
переписываются.

## Формат данных

Данные лежат в четырёх ключах localStorage: `finance.accounts`, `finance.categories`,
`finance.operations`, `finance.settings`. Формат версионируется полем `version` в записи
настроек — это точка входа для будущих миграций формата.

Стартовый набор категорий применяется один раз — когда ключа категорий ещё нет. Сохраняется он
отдельным JSON-файлом в репозитории: это данные, а не логика, и пользователь может менять набор
без правки кода.

Суммы в операциях и остатках счетов хранятся в целых минорных единицах.

## Ошибки хранилища

Недоступное хранилище (приватный режим браузера) и повреждённые данные не приводят к падению
приложения: пользователь видит сообщение о проблеме, остальные ошибки уходят в консоль без
stacktrace в интерфейсе.
