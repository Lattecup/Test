# API

## Назначение серверной части

Серверная часть — каркас и контракт. Приложение состоит из слоёв `routes → services →
repositories`, доменные типы в нём те же, что и на стороне интерфейса, но реализаций хранилища
пока нет. Контракт зафиксирован в OpenAPI (`server/openapi/openapi.yaml`) — это граница, по
которой вторая версия приложения заменит локальное хранилище на API-клиент.

## Эндпоинты

- `GET /api/health` — проверка доступности сервера, отвечает `200` с `{"status": "ok"}`;
- `GET`/`POST /api/accounts`, `/api/categories`, `/api/operations`, `/api/reports`,
  `/api/settings` — доменные эндпоинты, отвечают `501 Not Implemented`: хранилища на сервере ещё
  нет.

Ответ `501` содержит код ошибки, сообщение и запрошенные метод и путь.

## Формат ошибок

Ошибка отдаётся объектом с полем `error`, внутри которого код и сообщение. Доменные ошибки
(ситуации, которые должен исправить пользователь) имеют собственные коды и статусы; любые другие
ошибки отдаются как `500` с кодом `INTERNAL_ERROR` и без stacktrace в ответе — stacktrace пишется
в консоль.

## Сопутствующее

Сервер принимает JSON-тела запросов и разрешает кросс-доменные запросы, чтобы локальный интерфейс
мог обращаться к нему без прокси.
