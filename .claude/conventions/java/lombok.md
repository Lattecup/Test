# Lombok

[← Назад](index.md)

Lombok используется, чтобы убрать шаблонный код — конструкторы, геттеры,
сеттеры. Применяется только там, где это реально сокращает код, а не маскирует
сложность.

## Где уместно

- **Сервисы и компоненты с final-полями** — `@RequiredArgsConstructor` вместо
  ручного конструктора; final-поля автоматически попадают в параметры, нет
  риска забыть зависимость
- **DTO** — `@Value` (иммутабельный, без setter) или `@Data` (мутабельный);
  предпочитать `record` для иммутабельных DTO, Lombok — для изменяемых классов
- **Value-объекты** — `@Value`
- **Holder/result-классы** — `@Getter`/`@Setter` или `@Data`

## Где НЕ уместно

- **JPA entity** — `@Data` противопоказан: `equals`/`hashCode`/`toString` с
  bidirectional-связями дают бесконечную рекурсию, а Hibernate требует
  `@NoArgsConstructor` и не дружит с полностью иммутабельными POJO. Для
  entity: `@Getter` на полях + `@NoArgsConstructor`; сеттеры — только если
  доменная логика их реально требует
- **Классы-«портянки»** — если `@Data` нужен, чтобы скрыть 15–20 полей,
  вероятно класс делает слишком много; разбить, а не маскировать Lombok'ом

## Дополнительно

- Не смешивать Lombok и ручные геттеры/сеттеры в одном классе — либо одно,
  либо другое
- `@ToString`/`@EqualsAndHashCode` — явно перечислять поля через `of = {...}`
  или исключать связи (`@ToString.Exclude`, `@EqualsAndHashCode.Exclude`), иначе
  рекурсия и ленивые коллекции в hashCode
