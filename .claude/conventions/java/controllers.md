# Контроллеры

[← Назад](index.md)

- Реализация контроллера в `controller/` **имплементирует интерфейс** из
  `controller/api/`. Без парного интерфейса в `controller/api/` контроллер не
  готов к коммиту
- Интерфейс из `controller/api/` содержит всё Swagger-описание эндпоинта:
  `@Tag` на интерфейсе, `@Operation` на методах, `@ApiResponse` для кодов
  ответа, `@Parameter` для параметров
- Реализация **не дублирует** эти аннотации — только инфраструктурные:
  `@RestController`, `@RequestMapping`, security, валидация
- Имя интерфейса совпадает с именем контроллера + суффикс `Api`
  (`TaskController` → `TaskApi`)

## Зачем разделение

- Swagger-схема формируется по интерфейсу; правки OpenAPI не трогают реализацию
- DI / security / валидация остаются на реализации, где им место
- Сгенерированный по Swagger клиент не тянет DI-зависимости в свой код
